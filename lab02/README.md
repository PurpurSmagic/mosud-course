## Мощности

| Величина | Способ подсчёта | Значение |
| --- | --- | ---: |
| A, строки с повторами | `COUNT(*)` | 1 037 |
| A, уникальные товары | `COUNT(DISTINCT product_id)` | 841 |
| B, строки с повторами | `COUNT(*)` | 811 |
| B, уникальные товары | `COUNT(DISTINCT product_id)` | 647 |
| A ∪ B | `UNION` | 1 395 |
| A и B с сохранением повторов | `UNION ALL` | 1 848 |
| A ∩ B | `INTERSECT` | 93 |
| A − B | `EXCEPT` | 748 |
| B − A | `EXCEPT` | 554 |

## Вывод о дубликатах

- Исходные выборки A и B содержат по одной строке на позицию заказа. Один товар может встречаться в нескольких позициях, поэтому число строк больше числа уникальных товаров.
- `UNION ALL` сохраняет все 1 848 строк. `UNION` оставляет 1 395 уникальных товаров. Разница в 453 строки складывается из 196 повторов внутри A, 164 повторов внутри B и 93 товаров, общих для обоих штатов.
- Проверка через `EXCEPT` в обе стороны показала, что порядок операндов `UNION` и `INTERSECT` можно поменять без изменения состава результата. У разности при перестановке операндов остаются 748 товаров только слева и 554 только справа.
- Пересечение через `EXISTS` с `DISTINCT` совпадает с `INTERSECT` по всем 93 товарам. Если убрать `DISTINCT`, в результате повторяются 32 товара. Например, `9ecadb84c81da840dbf3564378b586e9` встречается 6 раз.

## Контрольные вопросы

1. **Почему `UNION` обычно дороже `UNION ALL`?** Для удаления дублей PostgreSQL обычно использует сортировку или хеширование. `UNION ALL` сохраняет все строки и обходится без этого шага.
2. **Почему по выводу без `ORDER BY` нельзя судить о порядке кортежей?** Отношение не имеет собственного порядка. Без `ORDER BY` порядок выдачи зависит от плана выполнения и может измениться.
3. **Чем множество отличается от мультимножества?** Элемент множества встречается один раз. В мультимножестве одинаковые элементы могут повторяться, и у каждого значения есть кратность.
