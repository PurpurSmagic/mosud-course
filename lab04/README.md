## Решение

### Определение клиента без отзывов

Клиент определяется по `customer_unique_id`. Один человек может оформить заказы с разными `customer_id`. Поэтому сначала собираются все его заказы, затем проверяется отсутствие отзывов. Вариант 8 не ограничивает статус заказа, поэтому учитываются все статусы. Запись без идентификатора человека исключается. Клиент с идентификатором, у которого ещё нет заказов, удовлетворяет условию.

| Пункт задания | Реализация |
| --- | --- |
| Основной запрос из трёх таблиц | `customers → orders → order_reviews`, группировка по человеку |
| Кратность каждого соединения | Указана в таблице ниже |
| Сохранение строк при отсутствии связи | Два `LEFT JOIN` сохраняют клиента без заказов и заказ без отзывов |
| Антисоединение | `HAVING count(r.order_id) = 0` и независимая проверка через `NOT EXISTS` |
| Ошибочное соединение | Позиции и отзывы присоединяются напрямую к заказу |
| Исправление | Позиции и отзывы отдельно группируются по `order_id` |
| Реляционная алгебра | Левые соединения, группировка, выборка и проекция записаны ниже |

У 41 клиента есть как заказ с отзывом, так и заказ без него. Если сразу применить `WHERE r.order_id IS NULL` к соединению отдельных заказов, эти люди попадут в выборку. Условие `HAVING count(r.order_id) = 0` проверяет человека целиком.

### Кратности

| Соединение | Кратность | Что это означает |
| --- | --- | --- |
| Человек → записи `customers` по `customer_unique_id` | 1:N | Один идентификатор человека может встречаться у нескольких `customer_id` |
| `customers → orders` по `customer_id` | 1:N по схеме | Каждый заказ связан с одной записью клиента. Внешний ключ допускает несколько заказов на запись |
| `orders → order_reviews` по `order_id` | 1:N | У заказа может быть от нуля до нескольких строк отзывов |
| `orders → order_items` по `order_id` | 1:N | У заказа может быть от нуля до нескольких позиций |
| `orders` → каждая сгруппированная таблица | 1:0..1 | После группировки на один заказ приходится максимум одна строка с количеством |
| Исправленный итог ↔ ошибочный итог по `order_id` | 1:1 | В каждом итоге есть одна строка на каждый заказ |

### Почему изменяются суммы и COUNT

Если у заказа 11 позиций и 2 отзыва, прямое соединение даёт 22 пары «позиция — отзыв». Именно это произошло у заказа `5a3b1c29a49756e75f1ef513383c0c12`. В ошибочном запросе `count(r.order_id)` посчитал 22 отзыва. Предварительная группировка дала 11 позиций и 2 отзыва. При отсутствии дочерних строк левое соединение сохраняет заказ, а `coalesce` подставляет ноль в соответствующий счётчик.

### Реляционная алгебра

Обозначим таблицы клиентов, заказов и отзывов через `C`, `O` и `R`. Оператор `⟕` — левое внешнее соединение, `γ` — группировка с агрегатами. Для основного запроса используется расширенная реляционная алгебра.

```text
C₁ = σ[C.customer_unique_id IS NOT NULL](C)
J₁ = C₁ ⟕[C.customer_id = O.customer_id] O
J₂ = J₁ ⟕[O.order_id = R.order_id] R
G  = γ[C.customer_unique_id; COUNT(DISTINCT O.order_id) → order_count,
       COUNT(R.order_id) → review_count](J₂)
Q  = π[customer_unique_id, order_count, review_count](σ[review_count = 0](G))
```

### Контрольные вопросы

**1. Почему соединение `order_items` и `order_payments` по одному `order_id` может завысить `SUM`?** Каждый платёж соединяется с каждой позицией заказа. При двух позициях сумма каждого платежа войдёт в итог дважды. Отдельная агрегация обеих таблиц по заказу сохраняет исходные суммы.

**2. В чём отличие `LEFT JOIN ... WHERE right.id IS NULL` от `NOT EXISTS`?** Первый способ ищет пустую правую сторону по столбцу, который у совпавшей строки гарантированно заполнен. Второй проверяет отсутствие любой подходящей строки. Для поиска клиентов оба способа должны учитывать все заказы одного человека.

**3. Как представить эквисоединение через декартово произведение и выборку?** Формула `C ⋈[C.customer_id = O.customer_id] O = σ[C.customer_id = O.customer_id](C × O)` оставляет из всех пар «запись клиента — заказ» только пары с одинаковым ключом.

## Проверка и сдача

На данных Olist оба способа нашли **716 клиентов без отзывов**. Две разности множеств через `EXCEPT` пусты. Прямое соединение завысило счётчик у 9 690 заказов и дало 113 131 отзыв. Исправленный запрос вернул **99 224** — столько же строк в исходной таблице `order_reviews`.
