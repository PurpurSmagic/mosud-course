# МОСУД Практическая работа 5

**Кванторы EXISTS и реляционное деление**

Усачев И.А., группа ИНБО-21-23, вариант **8**. Среда — PostgreSQL 17, база и схема `olist` из первой практики.

Требуется найти товарные категории, которые встречались в доставленных заказах покупателей каждого из трёх штатов **MS, MT и GO**. Дополнительно найдены продавцы, у которых были продажи во всех трёх штатах.

## Решение

### Формализация

Делитель `S = {MS, MT, GO}` содержит штаты Мату-Гросу-ду-Сул, Мату-Гросу и Гояс. Штат покупателя берётся из `customers.customer_state`. Заказ входит в расчёт при `orders.order_status = 'delivered'`.

Отношение `R(category, state)` содержит уникальные пары из названия товарной категории и штата покупателя. Для каждой позиции категория берётся из `products.product_category_name`. Пары с неизвестной категорией или штатом исключены. Множество кандидатов `U = π_category(R)` включает категории, доставленные хотя бы в один известный штат Бразилии. Оно остаётся одним и тем же при изменении делителя.

Категория входит в ответ, если для каждого штата из `S` есть соответствующая пара в `R`.

```text
Q = {c ∈ U | ∀s ∈ S (c, s) ∈ R}
Q = U − π_category((U × S) − R)
```

| Пункт задания | Реализация в SQL |
| --- | --- |
| Задать три обязательных штата | CTE `target_states` задаёт `MS`, `MT`, `GO` для временной таблицы `lab05_target` |
| Двойной `NOT EXISTS` | `lab05_by_exists` ищет категории без пропущенных штатов |
| `GROUP BY / HAVING` | `lab05_by_count` считает разные совпавшие штаты |
| `EXCEPT` и `NOT EXISTS` | `lab05_by_except` проверяет, пуста ли разность штатов |
| Сравнить результаты | `lab05_differences` вычисляет разность для каждой пары методов в обоих направлениях |
| Показать заказы одной категории | Диагностический запрос считает разные `order_id` по штатам |
| Проверить пустой делитель | Те же три запроса повторяются при пустой `lab05_target` |
| Найти продавцов | После восстановления делителя последний запрос выводит все подходящие `seller_id` |

### Почему методы эквивалентны

Двойной `NOT EXISTS` проверяет, существует ли обязательный штат, в котором категория ни разу не продавалась. Если такого штата нет, категория проходит.

В варианте с группировкой `COUNT(DISTINCT t.customer_state)` считает только штаты, совпавшие с делителем. Продажи в других штатах и повторные заказы не увеличивают это число. Для варианта 8 требуется совпадение по всем трём штатам.

В третьем варианте `EXCEPT` вычитает штаты продаж категории из множества обязательных штатов. Условие `NOT EXISTS` выполняется, когда в разности не осталось строк.

На данных Olist каждый способ вернул **47 категорий**. Во всех шести попарных сравнениях `difference_rows = 0`. Таким образом, совпали и количество категорий, и их названия.

### Диагностическая таблица

SQL автоматически выбирает первую по алфавиту найденную категорию. Для `agro_industria_e_comercio` получилось **5** доставленных заказов в GO, **3** в MS и **2** в MT. Во всех трёх штатах есть хотя бы один заказ. Если в одном заказе несколько товаров этой категории, `COUNT(DISTINCT order_id)` учитывает его один раз.

### Пустой делитель

Внутри транзакции скрипт временно удаляет все строки из `lab05_target` и обращается к тем же трём представлениям. При пустом множестве обязательных штатов невозможно указать штат, в котором требование нарушено. Поэтому условие «для всех» истинно для каждой категории из `U`. Все три реализации вернули **73 категории**.

В запросе с группировкой `LEFT JOIN` сохраняет категории-кандидаты. Для каждой из них число совпавших штатов равно нулю, как и размер пустого делителя. Отдельный пример с обычным `JOIN` дал ноль категорий, поскольку при таком соединении все строки исчезли до группировки.

После проверки `ROLLBACK TO SAVEPOINT` восстанавливает три штата варианта. Дополнительный запрос нашёл **163 продавца**, у которых были доставленные заказы покупателей каждого из этих штатов. Для отбора продавцов достаточно продажи любого товара, в том числе товара с незаполненной категорией.

### Контрольные вопросы

**1. Как переписать «для всех x выполняется P(x)» через «не существует»?**

`∀x ∈ S P(x) ⇔ ¬∃x ∈ S ¬P(x)`. В этой работе внешний `NOT EXISTS` ищет отсутствие контрпримера, а внутренний проверяет отсутствие продажи в конкретном штате.

**2. Почему COUNT(DISTINCT state) должен сравниваться с мощностью делителя?**

После отбора только обязательных штатов множество совпадений является подмножеством делителя. Равенство их размеров означает, что встретился каждый обязательный штат. Так, три заказа из одного штата дают одно совпадение из трёх.

**3. Что происходит с универсальным условием, если множество обязательных элементов пусто?**

Условие выполняется для каждого кандидата. В этой работе результатом становится весь `U`, включая категории, у которых не было продаж в MS, MT и GO.
