# МОСУД Практическая работа 6

**Подзапросы и логика предикатов. Вариант 8.**

Усачев И.А., группа ИНБО-21-23. Требуется найти продавцов, у которых средняя стоимость доставки выше общей средней стоимости доставки. Решение выполнено на PostgreSQL 17 в схеме `olist`. [lab06.sql](lab06.sql)

## Принятая семантика

Одна строка `olist.order_items` — одна позиция заказа. Стоимость её доставки хранится в `freight_value`. Для каждого продавца вычисляется средняя по его позициям. Общий порог — средняя по всем позициям, поэтому вклад продавца в неё зависит от числа позиций. Вариант не задаёт ограничений по статусу заказа.

`AVG` пропускает `NULL` и учитывает нулевую стоимость. У продавца без позиций с известной стоимостью средняя равна `NULL`, и такой продавец не проходит сравнение. Условие строгое — `seller_avg > overall_avg`. При равенстве продавец также исключается. Округление до двух знаков используется только для показа.

## Эквивалентность

В основном решении подзапрос берёт позиции по идентификатору текущего продавца. Во втором решении `GROUP BY seller_id` заранее формирует одну строку на продавца. В обоих случаях каждая позиция с известной стоимостью входит в общий порог ровно один раз.

На Olist оба способа нашли **1 221 продавца**. Колонки `only_main` и `only_alternative` обе равны нулю. Это означает, что совпали идентификаторы продавцов и обе неокруглённые средние для каждого из них. При расхождении SQL останавливает запуск с ошибкой.

## ANY и ALL

Условие `overall_avg < ANY (...)` проверяет, есть ли у продавца хотя бы одна позиция с доставкой дороже общей средней. Условие `overall_avg < ALL (...)` требует этого для каждой позиции с известной стоимостью.

Например, у продавца `001cca7ae9ae17fb1caed9dfb1094831` средняя равна **37,05** и превышает общий порог. В выводе `any_item_above = t`, а `all_items_above = f`. У этого продавца часть позиций проходит порог, а часть — нет.

На пустом множестве `ANY` даёт `false`, а `ALL` — `true`. На множестве `{5, NULL}` выражение `10 > ANY (...)` истинно благодаря сравнению с 5. Для `10 > ALL (...)` результат неизвестен, поэтому в последнем запросе `all_with_null_is_unknown = t`.

## Контрольные вопросы

**1. Чем коррелированный подзапрос отличается от независимого?**

Коррелированный подзапрос использует значение из внешней строки. Здесь при смене `s.seller_id` меняется набор позиций для вычисления средней продавца. Независимый подзапрос общей средней можно выполнить отдельно от запроса продавцов.

**2. В каких случаях EXISTS логически удобнее IN?**

`EXISTS` удобен, когда нужно узнать, есть ли связанная строка, удовлетворяющая нескольким условиям. Например, так можно проверить наличие у продавца позиции с известной стоимостью доставки. Для проверки отсутствия подходит `NOT EXISTS`. Если в подзапросе для `NOT IN` встретится `NULL`, сравнение при отсутствии совпадения даст неопределённый результат.

**3. Почему скалярный подзапрос должен возвращать не более одной строки?**

Внешнему выражению нужно одно значение. Ноль строк даёт `NULL`, одна строка с одним столбцом даёт его значение, несколько строк вызывают ошибку. В этой работе каждый `AVG` без `GROUP BY` возвращает одну строку даже при пустом входе.
